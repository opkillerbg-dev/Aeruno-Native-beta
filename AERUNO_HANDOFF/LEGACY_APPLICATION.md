# Legacy application reference (Arya Fit / AERUNO v150)

Tags: see `../START_HERE.md`. `LEGACY/` = `AERUNO_HANDOFF/legacy-reference/`. Source: the ZIP described in `SOURCE_MANIFEST.md`. "Works on the phone" is never claimed here; see `FEATURE_INVENTORY.md` for test status.

## 1. Architecture in one paragraph
A **Capacitor 6 WebView app**. The UI and almost all logic are plain **ES5 JavaScript with no framework and no bundler**, served as-is from `LEGACY/web/` (Capacitor `webDir`) [V `LEGACY/capacitor.config.json`, `LEGACY/package.json`]. CI generates the Android project with `npx cap add android`, then copies in hand-written **Java** from `LEGACY/native/` and patches the manifest/Gradle with scripts in `LEGACY/tools/` [V `LEGACY/.github/workflows/build.yml`, `LEGACY/tools/android-setup.sh`]. There is no committed `android/` folder. The UI talks to native code through Capacitor plugins (`Capacitor.Plugins.X`) and one injected JS interface (`window.AxInsets`).

```
index.html -> css (20 files) + 68 classic <script> files in a fixed order, one shared global scope
   |  Capacitor bridge (Capacitor.Plugins.RunEngine / Steps / SyncFile / AppWidget / AppIcon + stock plugins)
   v
MainActivity (BridgeActivity) -> plugin classes (Java) -> services: RunService (GPS), StepsPlugin.Svc (steps)
                                                       -> helpers: NotifKit, VoiceKit, WidgetKit, widget providers
Storage: localStorage "aryaApp2" (WebView) + IndexedDB "aryafit-lib" + Android SharedPreferences (native side)
```

## 3. Frontend structure
**Page:** `web/index.html` holds markup for the app shell, the sheets, the splash and the views, plus two tiny theme-preload scripts. Scripts are classic (not modules) and share one global scope; **order matters** (list: `<script src>` order in `index.html`). `js/boot.js` loads near the end; the V2 files (`js/ui/v2-*.js`) load last [V].

**Navigation** [V `index.html`, `js/core/sheets-views.js`]
- Bottom bar `#ax-nav` with five tabs (`data-v`): `home` (Today), `plan` (Plan), `timers` (Move), `prog` (Progress), `set` (Me/Settings). Labels in `index.html`: Today, Plan, Move, Progress, Me.
- Views are `<section>` elements `ax-v-home`, `ax-v-plan`, `ax-v-timers`, `ax-v-prog`, `ax-v-set`, `ax-v-plans`, plus the day view `ax-day`. `go(v)` in `js/core/sheets-views.js` shows one view of `VIEWS=["home","plan","timers","prog","set","plans"]` (and calls `axGuard()` unless going home).
- Sheets/dialogs: `axSheet(title, html)` in the same file renders into `#ax-sht/#ax-shb`. Android back button: `js/core/lifecycle.js` (history guard) and `js/features/backnav.js` (@capacitor/app).
- V2 shell: `js/ui/v2-shell.js` (navigation, active-session shortcut, account popover). Tab transitions: `js/ui/motion.js`.

**Screens (by tab)** [V file headers]: Today/Home (`js/ui/home.js`, `js/ui/v2-today.js`, readiness in `features/readiness.js`, weather card `features/weather.js`); Plan (`core/plan-ui.js`, `ui/v2-plan.js`, builder `features/builder.js`); Move/timers and runs (`core/timers-run.js`, `core/run-extras.js`, `ui/v2-session-run.js`, hands-free player `features/handsfree.js`); Progress (`core/progress-share.js`, `ui/v2-progress.js`, `features/prs.js`, `weekly.js`, `bodyheat.js`, `core/body-map.js`); Me/Settings (`ui/settings.js`, `ui/v2-settings.js`, `ui/v2-glass-studio.js`, `ui/help.js`); first-run wizard (`features/onboard.js`, `onboard-entry.js`).

**CSS** (20 files in `web/css/`): `base.css` (97 KB, original), `boot.css`, `run-polish.css`, `perf-fallback.css`, `liquid.css`, `heavy-glass-nav.css`; and `css/v2/`: `tokens`, `fonts`, `typography`, `components`, `shell`, `today`, `plan`, `progress`, `session-run`, `exercises-settings`, `polish`, `bridge`, `liquid`, `glass-studio`. V2 tokens are scoped under `html.v2` so V1 stays untouched [V `css/v2/tokens.css`]. V2 palette is **dark** (`--v2-bg:#000`, accent `#30d158`), unrelated to the new AERUNO palette (`DESIGN_SYSTEM.md`).

**V2 layering** [V headers]: the `v2-*.js` files are "presentation enhancers" that restyle and rearrange the existing DOM; "original handlers remain authoritative". `js/ui/perf.js` is a performance governor that lowers cost during scroll; `js/core/adaptive-glass.js`, `js/ui/v2-liquid.js` and the "Lite" mode (localStorage `axLite`, `axLiteAuto`; Lite option in `ui/v2-settings.js`) control glass cost. Why V2 lagged is **unproven** [D `AGENTS.md` section 1].

## 5. Global state and storage
- Globals in `js/core/state.js`: `KEY2="aryaApp2"`, `OLDK="arya28v1"`, `APP` (the whole saved object), `st` (progress), `PR` (preferences), `ND=28` days, `NW=4` weeks. `save()` = `localStorage.setItem(KEY2, JSON.stringify(APP))` [V].
- Accessors in `state.js`: `axPlan`, `axSched`, `axEdits`, `axRoutes`, `axRsum`, `axSrc`, `axShiftSt`, `axEditWorkout`, `todayIdx`.
- Storage safety (`js/core/store.js`): `AXSCHEMA=2`; migrations in `AXMIG` (`{to:1,name:"baseline"}`, `{to:2,name:"profile"}`); damaged-data recovery and snapshots via `axLsGet/axLsSet/axParse/axValidApp/axRunMig/axStoreRead/axStamp/axSnap` [V]. Tested by `tests/store.test.js`.
- Details of keys, schema, IndexedDB and native preferences: `DATA_AND_MIGRATION.md`.

## 6. Capacitor integration and native layer
- `LEGACY/native/java/MainActivity.java` extends `BridgeActivity`, registers the custom plugins, goes edge-to-edge, exposes `window.AxInsets` (insets and bar style) to JS, and requests a high refresh rate [V; the "120 Hz" value is from the code, not measured].
- Custom plugins [V `@CapacitorPlugin`/`@PluginMethod` in each file]:

| JS name | Java class | Role |
|---|---|---|
| `RunEngine` | `RunEnginePlugin` | Start/stop/state/route of a GPS run, speak text, list voices, open URLs |
| `Steps` | `StepsPlugin` | Step counting status/start/history/keepAlive/battery settings |
| `SyncFile` | `SyncFilePlugin` | Pick/read/write/unlink a user-chosen file (Storage Access Framework) |
| `AppWidget` | `AppWidgetPlugin` | Push a JSON snapshot to the home-screen widgets |
| `AppIcon` | `AppIconPlugin` | Switch between 6 launcher icons |

- Services and helpers [V]: `RunService` (foreground service, location; location updates from the GPS provider every second, step sensor; track and route kept in **static in-memory fields**, start type not sticky), `RunTrack` (pure Java track filter), `StepsPlugin.Svc` (foreground service, type health, step-counter sensor, per-day totals in SharedPreferences) and `StepsPlugin.Boot` (restarts after boot/update), `NotifKit`/`NotifText` (notification builders), `VoiceKit` (TextToSpeech), `WidgetKit` and `Steps/Today/ComboWidgetProvider` (widgets).
- Manifest additions in `tools/patch-manifest.sh`, `tools/patch_icons.py`, `tools/patch_widgets.py`; permission inventory in `LEGACY/docs/PERMISSIONS.md` [D, partly V].
- Stock Capacitor plugins used from JS [V grep]: `LocalNotifications` (`features/nudges.js`, `core/timers-run.js`), `StatusBar` (`core/native-ui.js`), `App` (`features/backnav.js`), `Haptics`, `Share`, `Filesystem`. `BackgroundGeolocation` is referenced only in `core/timers-run.js` as a **fallback when `RunEngine` is absent**.

## 7. GPS tracking
JS side (`core/progress-share.js` defines `ENG`, `engStart`, `engPush`; `core/timers-run.js` owns the run session object `TM` and `trkOff()`): when running natively, `ENG.requestPermissions()` then `ENG.start(opts)`; JS pushes timer state (elapsed, paused, phase, round) to the service with `engPush`; JS polls `state()`. Native side: `RunService` receives location fixes, filters them through `RunTrack`, accumulates distance/route in memory and shows a foreground notification. The **in-progress run is also persisted by JS in localStorage `aryaRun1`** (mode, distance, track...), so run recovery depends on the JS layer, not on native storage [V `timers-run.js`, `RunService.java`]. Filtering logic exists twice: `RunTrack.java` (native) and `runcalc.js` (JS) [V]. Run summary/route/share: `features/runsummary.js`, `routemap.js`, `livemap.js` (offline SVG), `runcard.js`, `gpx.js`, `prs.js`.

## 8. Step counting
`StepsPlugin` (Java) runs `Svc`, a foreground service (manifest type `health`) reading `Sensor.TYPE_STEP_COUNTER` and keeping per-day totals in SharedPreferences `arya_steps` under keys `d_yyyy-MM-dd` [V]. `Boot` restarts it after reboot and app update. JS mirror and UI: `core/steps-progress.js`; steps history is copied into `PR.ds` for backups (`packFresh` in `data-io.js`) [V]. Widgets read the same preferences.

## 9. Workout logic
- Plans: stored in `APP.plans` in the "arya-plan" format; generated by `plangen.js` (docs: `docs/onboarding/04_PLAN_ENGINE.md`), built by hand in `builder.js`, edited via sheets in `core/sheets-views.js`; user edits in `axEdits`.
- Levels and weak points: `levelcalc.js` (`docs/onboarding/03_LEVELS_AND_WEAK_POINTS.md`); retest every 4 weeks: `retest.js`.
- Progression and logging: `progression.js` (1-tap set logging, progression hint, PR pills, deload hint), `loads.js` (gym weights stored in kg: `PR.wtLog`), `readiness.js` (0-100 score adjusts the plan), `coach.js` + `coachcalc.js` ("Smart week"), `swap.js` (exercise swap), `weekly.js` (weekly card).
- Profile: `core/profile.js` (validation, draft `aryaOnboardDraft`); data model doc `docs/onboarding/02_DATA_MODEL.md`.

## 10. Timers
`core/timers-run.js` (18.5 KB): session object `TM` with modes `"cd"` (countdown), `"sw"` (stopwatch), `"iv"` (intervals) [V]; wake lock, voice cues via `run-extras.js` and `features/voice.js`; hands-free player `features/handsfree.js`; V2 presentation `ui/v2-session-run.js`.

## 11. Exercise library
- Built-in: `features/exdb.js` (108 exercises, one-line how-to each; 62 have pictures) [S/V]; pictures `web/images/exercises/*.webp` (frames a/b/c/d) with masks in `web/images/exercise-masks/`; mapping/loader `core/exercise-media.js`; animation `features/animate.js`.
- Optional online library (public-domain "free-exercise-db"): `features/library.js`, stored in **IndexedDB `aryafit-lib`** (store `kv`), downloaded only if the user opts in [V].
- Body map: `core/body-map.js` (67 KB inline SVG anatomy), `features/bodyheat.js`.

## 12. Analytics and history
Progress tab (`prog()` in `core/sheets-views.js`, `axPs()` in `core/steps-progress.js`; V2 enhancer `ui/v2-progress.js`): history, overview, PRs (`prs.js`), weekly review card (`weekly.js`), run history with route (`routemap.js`), streaks and goals in Home/Progress code. Run records are stored per plan in `rsum` and `routes` inside `APP.plans` [V `data-io.js` `pack()`].

## 13. Backup, import/export, sync
`core/data-io.js`: `pack()`/`packFresh()` build the export envelope, `doImport()` restores, `clean*` functions validate; export opens the Android share sheet; `features/backup.js` nudges backups; `features/sync.js` keeps one user-picked file (e.g. Google Drive via the Android file picker) updated and pulls newer data. Format details: `DATA_AND_MIGRATION.md`.

## 14. Notifications, widgets, voice, icons, weather
Local notifications and "nudges" (hydration, check-in, move break, evening walk, weekly summary, comeback): `features/nudges.js`; run/step notifications: native `NotifKit`/`NotifText`; widgets: `features/widget.js` + `WidgetKit` + three providers; voice: `features/voice.js` + `VoiceKit`; icon picker: `features/appicon.js` + `AppIconPlugin` + `LEGACY/tools/patch_icons.py`; weather: `features/weather.js` (opt-in, `api.open-meteo.com` [D `docs/PERMISSIONS.md`]).

## 15. Offline and boot
Service worker `web/sw.js` (cache `arya-v150`) precaches the shell (HTML, CSS, fonts, JS). Boot sequence: `js/core/lifecycle.js` runs init; `js/features/bootgate.js` + `js/boot.js` implement a "smart loading screen" that waits for a stable frame rate (max about 11 s) [V headers].
